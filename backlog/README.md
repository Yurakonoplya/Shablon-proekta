# План работ (бэклог)

Единственное место, где живут задачи на будущее. Второго списка дел в проекте нет.

Этот файл — витрина: **полный список задач одной строкой каждая**, чтобы понять расклад, не открывая ничего. Подробности задачи — в её файле рядом.

Значки: 🔴 сейчас · 🟡 следом · ⚪ потом.

## Задачи

- [ ] 🔴 [Заполнить CLAUDE.md и фундамент проекта](первичная-настройка-проекта.md) — расспросить владельца и закрыть пустые разделы.

## Как это устроено

**Задача — отдельный файл** с понятным именем, по которому ясно, о чём она (`подтверждение-почты-при-оплате.md`, а не `task-7.md`). Номеров не ставим: они говорят о порядке заведения, а не о смысле, и первыми расходятся с реальностью.

Внутри файла — четыре вещи и ничего больше: **зачем** (что будет не так, если не делать), **что должно получиться** (проверяемый признак, а не «станет лучше»), **что известно** (файлы, ограничения, ссылки — чтобы не искать заново), **границы** (чего в этой задаче не делаем).

Мелочь, которая укладывается в одну строку и не требует объяснений, файла не получает — она живёт строкой в списке выше. Файл заводится тогда, когда задаче есть что сказать о себе.

Сюда идут **только задачи**. Принятые решения — в [о-проекте.md](../project/о-проекте.md) и [технической архитектуре](../project/техническая-архитектура.md), «когда и почему решили» — в [журнале](../project/журнал/README.md).

**Закрытая задача уходит отсюда совсем, а не помечается галочкой.** Два шага: строка убирается из списка выше, а в [журнал](../project/журнал/README.md) ложится запись, что получилось и почему. Файл задачи после этого удаляется — он описывал замысел, а замысел уже заменён результатом; история правок его помнит.

В [архив](../archive/README.md) уезжает не задача, а объёмный материал, если работа его оставила: большой разбор, отчёт, прежняя версия документа. Пятнадцать строк замысла под это не подходят — их итог целиком укладывается в строку журнала.

Так этот файл остаётся списком будущего, а не отчётом о прошлом.
